# Store Submission Checklist — BioGlow Field Notebook

**Answer to "will this work as a real app downloadable from the App Store and Play
Store?"** Yes — *with the owner's own developer accounts*. This project is a standard
Expo / React Native app with production build and submit profiles already configured.
No code changes are needed to submit; what remains is account, asset and listing work
that only the account owner can do (stores require the owner to log in, pay, verify
identity, and accept their agreements — never share those passwords with anyone).

Identity already set in `app.json`:

| Item | Value |
| --- | --- |
| App name | BioGlow Field Notebook |
| Expo slug | `bioglow-field-notebook` |
| iOS bundleIdentifier | `com.satishnavudu.bioglowfieldnotebook` |
| Android package | `com.satishnavudu.bioglowfieldnotebook` |
| Version | `1.0.0` (iOS buildNumber `1`, Android versionCode `1` — EAS auto-increments production builds) |
| Permission strings | Camera, photo library, microphone and location usage descriptions are set for iOS, and the location/image-picker plugin permission strings for Android |

> If a different developer/organisation will publish the app, change the bundle ID /
> package to one they own **before the first store upload** — these IDs cannot be
> changed after an app is created in App Store Connect / Play Console.

---

## 0. Accounts (owner only)

- [ ] Expo account (free) — `eas login`
- [ ] Apple Developer Program — **$99/year**, owner must be 18+ / organisation verified
- [ ] Google Play Console developer account — **$25 one-time**, identity verification
      (government ID for personal accounts)

## 1. Production builds with EAS Build

Signing is handled by EAS Build using the owner's accounts: iOS distribution
certificate + provisioning profile are created and stored by EAS (it logs into the
owner's Apple account when prompted); the Android upload keystore is generated by EAS
and backed up there — also download and safely store a copy of the keystore, because
losing it complicates future Android updates.

```bash
npm install -g eas-cli
eas login
eas build:configure        # first time only — links project, writes extra.eas.projectId

# Google Play build — Android App Bundle (.aab), profile "production" in eas.json
eas build -p android --profile production

# App Store build — .ipa, profile "production" in eas.json
eas build -p ios --profile production

# Optional: direct-install Android test build (.apk), profile "preview"
eas build -p android --profile preview
```

Before building:

- [ ] `npm run typecheck` passes (`tsc --noEmit`)
- [ ] App tested on a real phone via Expo Go / preview build (camera, GPS, microphone,
      photo picker, CSV export all exercised — test the permission-denied paths too)
- [ ] Final icon (1024×1024, no transparency for iOS) and splash artwork replace the
      placeholders in `assets/`

## 2A. Submit to Google Play

Either automated:

```bash
eas submit -p android --profile production
```

(uses the `submit.production.android` profile in `eas.json` — track `production`,
release status `draft`, so a human still presses "publish" in Play Console), or manual:
download the `.aab` from the EAS build page and upload it in Play Console →
Production → Create release.

Play Console listing work:

- [ ] Create the app in Play Console with package `com.satishnavudu.bioglowfieldnotebook`
- [ ] Store listing: title (≤30 chars), short description (≤80), full description,
      app icon 512×512, feature graphic 1024×500, at least 2 phone screenshots
      (capture from the real app — Home, BioGlow form, Notebook)
- [ ] Privacy policy URL (public web page — see §3)
- [ ] Data safety form: **no data collected, no data shared** (entries, photos, voice
      notes and location stay on the device; nothing is transmitted)
- [ ] Content rating questionnaire (IARC) and target audience declaration
- [ ] App access / ads declarations: no ads, no account/sign-in required
- [ ] ⚠️ **Closed-testing gate for new personal accounts:** personal Play accounts
      created after 13 Nov 2023 must run a **closed test with at least 12 testers
      opted in for 14 continuous days**, then apply for production access, before a
      public release is allowed. Organisation accounts are exempt. Plan the timeline
      around this — it is Google's rule, not something EAS or this code can skip.
      Tip: recruit 14–15 testers in case someone drops out.
- [ ] Google review after submission typically takes days; answer any policy
      questions pointing to the on-device-only data model

## 2B. Submit to the Apple App Store

Either automated:

```bash
eas submit -p ios --profile production
```

(uses the `submit.production.ios` profile in `eas.json`; EAS will prompt for the
owner's Apple ID / App Store Connect details), or manual: download the `.ipa` and
upload it with Apple's **Transporter** app to App Store Connect, then attach the build
to the app version page.

App Store Connect listing work:

- [ ] Create the app in App Store Connect with bundle ID
      `com.satishnavudu.bioglowfieldnotebook`
- [ ] Listing: name (≤30 chars), subtitle, description, keywords, support URL
- [ ] Screenshots: at minimum 6.7" iPhone set (1290×2796) captured from the real app;
      add 6.5" set if required at submission time
- [ ] App icon 1024×1024 (already supplied by the build from `assets/icon.png`)
- [ ] Privacy policy URL (public web page — see §3) and App Privacy questionnaire:
      **Data Not Collected** (location/photos/audio are used on-device only and never
      leave the phone — answer consistently with this)
- [ ] Age rating questionnaire; export compliance is pre-answered
      (`ITSAppUsesNonExemptEncryption: false` is set in `app.json`)
- [ ] App Review notes: explain the app is fully offline, needs no login, and tell the
      reviewer how to try the BioGlow template, GPS button, photo and voice note —
      reviewers deny apps they cannot figure out
- [ ] ⚠️ Apple review typically takes 1–3 days once submitted, and a rejection is a
      conversation, not a ban: read the message, fix or explain, resubmit the same
      version where possible

## 3. Privacy policy (required by both stores)

Host one simple public page (any static site) and use its URL in both consoles. It
must truthfully say, for this app:

- All notes, photos, voice recordings and location tags are stored **only on the
  user's device** (AsyncStorage / local files).
- The app has **no accounts, no analytics, no ads, and no server** — nothing is
  collected, transmitted, sold or shared.
- Location/camera/microphone/photo permissions are used only when the user taps the
  matching button, for that entry.
- Deleting the app deletes its data; CSV export happens only when the user taps Export.
- A contact email for the developer.

If any of that ever changes (e.g. a future cloud sync in V3), update the policy and
both stores' privacy forms **before** shipping that version.

## 4. Final pre-flight

- [ ] Production `.aab` installed via Play internal/closed testing on a real Android phone
- [ ] Production `.ipa` installed via TestFlight on a real iPhone
- [ ] Fresh-install test: first entry saved with all permissions **denied** still works
      (typed location fallback), and with permissions **granted** (GPS/photo/voice)
- [ ] Listing screenshots/descriptions match the shipped glossy design
- [ ] Version/build numbers incremented for every re-upload (EAS `autoIncrement` is on
      for production)
